# エラーハンドリング

> **カテゴリ**: 機能追加
> **前提**: React + TypeScript + TailwindCSS + アトミックデザイン
> **難易度**: ★★★☆☆
> **所要時間目安**: 25〜40分

## このプロンプトの使い方

React ErrorBoundary、グローバルエラーハンドラー、HTTP エラー別処理、エラーロギングを含む包括的なエラーハンドリングシステムを構築する際に使用します。

---

## プロンプト

````text
以下の仕様に従い、包括的なエラーハンドリングシステムを構築してください。
既存の AGENTS.md および BLUEPRINT.md の規約に従ってください。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
■ 構成ファイル
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```
src/
├── components/
│   ├── atoms/
│   │   └── RetryButton.tsx          # リトライボタン
│   ├── molecules/
│   │   ├── ErrorMessage.tsx         # エラーメッセージ表示
│   │   └── ErrorFallback.tsx        # ErrorBoundary のフォールバックUI
│   └── organisms/
│       └── ErrorBoundary.tsx        # Error Boundary コンポーネント
├── components/pages/
│   ├── NotFoundPage.tsx             # 404 ページ
│   ├── ForbiddenPage.tsx            # 403 ページ
│   └── ServerErrorPage.tsx          # 500 ページ
├── hooks/
│   └── useErrorHandler.ts           # エラーハンドリングフック
├── utils/
│   ├── errorLogger.ts               # エラーロギングユーティリティ
│   └── errorHelpers.ts              # エラー判定ヘルパー（isApiError, isNetworkError 等）
├── types/
│   └── error.ts                     # エラー関連型定義
```

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
■ 1. ErrorBoundary
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
- class component で実装（getDerivedStateFromError + componentDidCatch）
- フォールバックUI をカスタマイズ可能な Props（fallback / fallbackRender）
- リセット機能（再試行ボタン → state をクリアして再レンダリング）
- onError コールバックでエラーロギング
- ページ単位 / コンポーネント単位で配置可能

### フォールバック UI
- エラーアイコン + メッセージ
- 「再試行」ボタン + 「ホームに戻る」ボタン
- 開発環境ではスタックトレースを表示
- レスポンシブ対応 + ダークモード対応

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
■ 2. HTTP エラー別処理
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
| ステータス | 処理 |
|-----------|------|
| 400 | エラートースト（リクエスト不正） |
| 401 | 認証ストアをクリア → ログインページへリダイレクト |
| 403 | 403 エラーページを表示 |
| 404 | 404 エラーページを表示 |
| 422 | フォームにバリデーションエラーを表示 |
| 429 | レート制限トースト + Retry-After 後にリトライ |
| 500 | エラートースト + リトライボタン |
| ネットワークエラー | オフラインバナー表示 |

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
■ 3. エラーページ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
各エラーページには以下を含める：
- エラーコード（大きなフォント）
- 説明テキスト
- 「ホームに戻る」ボタン
- 「前のページに戻る」ボタン
- モダンなデザイン（グラデーション + アニメーション）

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
■ 4. エラーロギング
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
- 本番環境: 外部サービス（Sentry 等）への送信（オプション）
- 開発環境: console.error にスタックトレースを出力
- エラー情報の構造化（タイムスタンプ、URL、ユーザーエージェント、エラー内容）

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
■ 5. 型安全なエラーハンドリング
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```typescript
// エラー型の判定（型ガード）
const isApiError = (error: unknown): error is ApiError => { ... };
const isNetworkError = (error: unknown): error is TypeError => { ... };

// catch ブロックでの使用
try { ... } catch (error: unknown) {
  if (isApiError(error)) {
    // ApiError 型として安全に扱える
  }
}
```

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
■ コーディング規約
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
- AGENTS.md のコーディング規約をすべて遵守する
- any 禁止（catch ブロックは unknown で受ける）
- アロー関数、JSDoc、日本語コメント
- ErrorBoundary のみ class component を許可
````
