# 障害対応フロー

> **カテゴリ**: 開発ワークフロー
> **前提**: React + TypeScript + TailwindCSS + アトミックデザイン
> **難易度**: ★★★☆☆
> **所要時間目安**: 15〜30分

## このプロンプトの使い方

本番環境で障害が発生した際に、AIエージェントに渡して検知→トリアージ→対応→原因分析→再発防止を体系的に進める際に使用します。

---

## プロンプト

````text
以下のフローに従い、報告された障害の対応を実施してください。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
■ 障害情報
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【ここに障害の詳細を記述する】
- 発生日時:
- 発生環境: （本番 / ステージング）
- 影響範囲:
- 症状:
- 再現手順:
- エラーメッセージ:

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
■ フェーズ 1: トリアージ（5分以内）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

### 重大度判定

| レベル | 基準 | 対応期限 |
|--------|------|---------|
| P0 (Critical) | サービス全停止、データ損失 | 即時 |
| P1 (High) | 主要機能の障害 | 4時間以内 |
| P2 (Medium) | 一部機能の障害（回避策あり） | 24時間以内 |
| P3 (Low) | 軽微な不具合 | 次回リリースまで |

以下を判定して報告:
1. 重大度
2. 影響範囲（影響を受けるユーザー数/機能）
3. 回避策の有無

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
■ フェーズ 2: 原因調査
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

### 調査手順
1. エラーログの確認（console.error、ネットワークエラー）
2. 直近のデプロイ内容の確認（git log で最新コミットを確認）
3. ブラウザのコンソール/ネットワークタブの確認
4. 再現手順の特定
5. 影響範囲の特定

### 確認すべきポイント
- [ ] 直近のデプロイが原因ではないか
- [ ] 外部サービス（API、認証、CDN）の障害ではないか
- [ ] ブラウザ固有の問題ではないか
- [ ] 環境変数の設定ミスではないか
- [ ] データの整合性の問題ではないか

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
■ フェーズ 3: 修正
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

### 修正方針
- `hotfix/` ブランチを作成する
- 最小限の修正に留める（根本対策は後日）
- AGENTS.md のコーディング規約を遵守する（any 禁止、アロー関数等）

### 修正後の確認
1. ローカルで再現手順を実行して修正を確認
2. ESLint / TypeScript コンパイルエラーが 0 件
3. npm run build が成功
4. 既存テストがすべて通る

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
■ フェーズ 4: デプロイ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
- hotfix ブランチを main にマージ
- 自動デプロイを監視
- デプロイ後に本番で修正を確認

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
■ フェーズ 5: ポストモーテム
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
````
